## 0. 现状与证据（为什么现在不可用）

| 观察 | 证据 |
| --- | --- |
| 左侧栏没有笔记本入口 | 真实页面 `document.querySelectorAll('.n-rowaction')` 有 2 个（会话行悬停按钮），但主面板打不开 |

| 浮层版本也崩 | 改用 `shell.overlay` 后，点开会话行按钮 → `slot entry crashed in 'shell.overlay': TypeError: f is not a function`（React Context.Consumer children 不是函数） |

| 右侧面板是半成品 | 只有列表；空态文案还指向一个不存在的左侧按钮；没有新建动作 |

**结论**：现有实现没有达到“能用”，必须先修渲染崩溃，再补齐两个入口和保存闭环。

## 2. 承载方案（需要你拍板）

| 方案 | 承载 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 浮层 `shell.overlay` | 右侧 960px 浮层 | 不依赖 `sidebar.panellist` | 与“右侧全局入口进主面板”的要求不符 |
| **B. 主面板 `main`（用户指定）** | 中央主区域 | 空间最大；右侧全局入口点开就是它 | 左侧必须有一个 `sidebar.panellist` 行来承载工作区入口（这是用户要的） |
| C. 右侧标签页内嵌 | 右栏 300–420px | 位置就在右侧 | 太窄 |

**按用户 2026-11-04 的澄清改为 B**：

- **左侧入口由左侧面板承载**：`sidebar.panellist` 一行「笔记本」，作用于**当前工作区**——没有就以工作区名在根层级建，已有就打开；行文案在「新建笔记本 / 打开笔记本」之间切换。
- **右侧全局入口**：右栏 `notes` 标签页 + 「全部笔记本」guide 入口，点开直接进**主面板**（`main`，key=`notes`），显示全部笔记本。

## 3. 入口设计

### 3.1 左侧（工作区级，左侧面板承载）

- 位置：`sidebar.panellist` 一行「笔记本」（**不是**「全部笔记本」）。
- 行为：点击 → `ensureWorkspaceNotebook(当前工作区)` → 没有就以工作区名建在根层级 → `selectPanel('notes')` 打开主面板并选中。
- 文案：`label` 用函数读模块级“当前工作区是否有笔记本”的状态，在「新建笔记本 / 打开笔记本」之间切换。
- 会话行悬停按钮保留为快捷方式（同一个动作），不另占位置。

### 3.2 右侧（全局入口 → 主面板）

- 位置：右侧栏注册 `notes` 标签页类型 + `guide` 入口「全部笔记本」（`sidebarRightTabs` / `sidebar.right.pane.tab`）。
- 行为：点入口 → `selectPanel('notes')`，在**主面板**显示全部笔记本（树 + 编辑器）。
- 标签页本身可作为“最近打开的笔记本”列表；点条目同样进主面板。
- 说明：本机 0.2.1-rc.5 的右栏没有“竖向面板列表”，所以“在那四项下面”只能落在右栏的「新标签页」入口；如果这不是你要的位置，需要你指出你屏幕上那四项的具体位置。

## 4. 分步实施与审核门

每一步完成后提交：**操作路径 + 截图 + console 无错 + 落盘证据**，你审核通过才进入下一步。

### Step 0：修渲染崩溃（阻断项）

- 在 `NotesApp` 外包 error boundary（已加），用 `componentStack` 定位 `f is not a function` 的具体组件；
- 逐个缩小（先空组件 → 工作区条 → 树 → 编辑器），找到崩溃点并修；
- 同时加 build 标记：`console.info('[dsh-notes] build <hash>')`，每次 reload 先确认加载的是新包。

**验收**：点左侧「笔记本」行 → 主面板出现笔记本界面，能看到工作区条和树，console 无 error。

**结果（2026-11-04 19:35，已通过）**：

- 崩溃根因：`@blocknote/mantine` 的 `MantineProvider` 在宿主 React 下渲染 Context.Consumer 失败（`f is not a function`）；
- 修法：改用 `@blocknote/react` 的 `BlockNoteViewRaw`（不引入 Mantine），编辑器包从 3476 KB 降到 3297 KB，CSS 264 KB → 45 KB；
- 真实浏览器证据：点左侧「笔记本」→ `.n-app` 出现；新建页 → `.bn-editor` 挂载；输入「周会记录测试 2026-11-04」→ 状态「已保存」→ 磁盘 `~/.dsh/notes/nb_hf9ak69vtt94/p_j6ltd8lvl39d.md` 有该文本；刷新页面后重新打开该页，文本仍在；console 无 error。

### Step 1：左侧入口闭环

- 会话行按钮 → 建/开 → 浮层选中；
- 文案切换；
- 无工作区时的禁用态。

**验收**：在两个不同工作区各点一次，生成两个根层级子笔记本，互不覆盖；重复点不重复建。

### Step 2：右侧「全部笔记本」

- 右栏标签页 + guide 入口；
- 顶部当前工作区 新建/打开；
- 列表点击打开浮层。

**验收**：从右侧入口进主面板，能看到 Step 1 建的两个笔记本；点条目能切换。

### Step 3：编辑与保存闭环

- 新建页 → 输入 → 800ms 自动保存 → 关闭浮层 → 重开 → 内容在；
- 刷新页面 → 内容仍在；
- Markdown 镜像文件存在且内容正确。

**验收**：真实浏览器操作录屏/截图 + `~/.dsh/notes/**` 文件证据。

### Step 4：边界与打磨

- 401/503 错误态、空态、冲突提示（409）、Esc 关闭、焦点、暗色、中英文；

**验收**：逐条对照截图。

### Step 5：最终验收

完整走一遍：新建工作区笔记本 → 写标题和正文 → 等自动保存 → 关闭 → 刷新页面 → 从右侧入口重开 → 内容一致 → 删除进回收站。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 客户端 bundle 缓存导致改动不生效 | 每次改动后看 console 的 build 标记；未更新则等待/重启 dsh web |
| 主面板与 `sidebar.panellist` 的绑定 | 左侧保留一行「笔记本」，正好提供 main 面板身份，也满足“左侧面板承载”；不再验证“无行也能开 main” |
| BlockNote 首开慢 | 骨架屏 + 懒加载（已有） |
| 数据目录已有测试数据 | 保留，不删；用两个工作区做隔离测试 |
| 工作区行无插槽 | 明确告知：左侧入口只能落在会话行悬停按钮；要工作区行按钮需替换 `sidebar.workspaces`（不默认做） |
